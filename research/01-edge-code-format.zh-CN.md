# 01 – DX 片边码格式

**问题**：35 mm 胶片片边上的 DX 条码中，信息究竟是怎样排列的？每个细节我们能有多大把握？

**简短回答**：两条相互紧贴、由二进制格组成的轨。上面的*时钟轨*是固定的定时图案；下面的*数据轨*带有固定的起始符、Part 1（第一部分，7 位）、一个空白格、Part 2（第二部分，4 位）、帧号（6 位）、半帧标志、一个空白格、一个偶校验位和固定的终止符，共 31 格。帧号扩展出现之前生产的胶片使用 23 格的版本，没有帧号字段。下文的每条规则都有至少两个相互独立的来源支持，并已在一张真实的负片上得到证实。

## 两条轨

条码位于齿孔与胶片边缘之间；它的确切位置和尺寸见[报告 05](05-reading-real-film.zh-CN.md)。它有两排，高度相同且彼此紧贴，所以同一列中的时钟条和数据条看起来就像一根高条：

- **时钟轨**靠近齿孔，在所有胶片上都一样。它告诉读码器每一格在哪里，以及条码的走向；
- **数据轨**沿着胶片边缘，承载信息。每一格要么是条（已曝光，1），要么是空（未曝光，0）。

柯达的专利 US 4,965,628 描述了“a clock track 500 and a data track 505 extending parallel with the clock track”（时钟轨 500，以及与时钟轨平行延伸的数据轨 505），维基百科的 *DX number* 条目则把时钟轨放在“closer to the sprocket holes”（更靠近齿孔）的位置。

## 31 格版式（带帧号）

各格按读取顺序从 1 开始编号，起点在时钟轨的宽标记处。

![DX 79-15 第 23 帧的 31 格版式：时钟轨和数据轨，附格号、各位权值和字段](img/layout-31.zh-CN.svg)

| 格 | 字段 | 位数 | 内容 |
|---|---|---|---|
| 1–6 | 起始符 | 6 | 总是 `101010` |
| 7–13 | Part 1，“film product class”（胶片产品类别） | 7 | 二进制，权重 64 32 16 8 4 2 1 |
| 14 | 未分配 | 1 | 总是 0 |
| 15–18 | Part 2，“film specifier”（胶片规格号） | 4 | 二进制，权重 8 4 2 1 |
| 19–24 | 帧号 | 6 | 二进制，权重 32 … 1（见[报告 02](02-frame-numbers.zh-CN.md)） |
| 25 | 半帧标志 | 1 | 1 = 两帧之间的“A”位置 |
| 26 | 未分配 | 1 | 总是 0 |
| 27 | 校验位 | 1 | 第 7–13、15–25 格的偶校验 |
| 28–31 | 终止符 | 4 | 总是 `0101` |

时钟轨：`1111101010101010101010101010111`，即先是一个占 5 格的标记，然后是 23 个空/条交替的单格（11 根细条），最后是一个占 3 格的标记。

维基百科的 *DX number* 条目列出了同样的字段，并标出了它们在 ISO 1007 中的章节号，从 §6.1.1.1 entry code（起始码）到 §6.1.1.8 exit code（结束码）。维基百科的 *DX encoding* 条目把帧号位和半帧位合起来描述为“a seven-bit frame/half-frame number”（一个 7 位的帧/半帧号），这与柯达专利中的“seven bits defining the frame number … defined as half frame intervals”（定义帧号的 7 位……以半帧间隔定义）一致。

## 23 格版式（无帧号）

1983 年最初的条码没有帧号字段：

![DX 79-7 的 23 格版式：时钟轨和数据轨，附格号、各位权值和字段](img/layout-23.zh-CN.svg)

| 格 | 字段 |
|---|---|
| 1–6 | 起始符 `101010` |
| 7–13 | Part 1 |
| 14 | 未分配，0 |
| 15–18 | Part 2 |
| 19 | 校验位 |
| 20–23 | 终止符 `0101` |

时钟轨：`11111010101010101010111`，即一个占 5 格的标记、15 个单格（7 根细条）、一个占 3 格的标记。

证据：zxing-cpp 的读码器和 Zint 的生成器都实现了这个版本（时钟轨各连续段的宽度为 `5, 1×15, 3`，长版本则为 `5, 1×23, 3`）；富士的专利 US 5,122,645 描述了一种带有“seven clock bars”（7 根时钟条）的 DX 码；Aurélien Lawley 区分了“short version”（短版本）和“long version”（长版本）；Antoine Mérino 的博客展示了一卷胶片，它的条码（DX 40-9，一个属于柯尼卡的编号）不带帧号。实践中：**时钟轨有 11 根细条表示 31 格版式，有 7 根表示 23 格版式。**

23 格条码并没有随着 1990 年的扩展而消失。柯达 1995 年申请的一项专利（US 5,665,950）仍把现有的读码器描述为“designed to read a 23-bit, two track DX bar code”（设计用于读取 23 位、双轨的 DX 条码）；柯达 1997 年申请的一项专利（EP 0838718）提到，有“a substantial usage of DX coded film”（大量 DX 编码胶片）不带帧号编码。哪些制造商用了哪种版式、一直用到什么时候，都没有查到；时间线见[报告 07](07-history-and-related-markings.zh-CN.md)。

### 区分两种版式要靠时钟轨

这是本项目的一个发现，已在单元测试中穷举验证：把 23 格条码填进 31 格的网格（先是它的 23 格，后面是空白格），得到的*总是*同一胶片的一个有效 31 格编码，帧号为整帧 10 或 42。短条码的校验格和终止符 `0101` 落进了帧号字段：校验格为空时得到帧 10，校验格有条时得到帧 42。这样，帧号字段贡献的是那根校验条（它本来就使 Part 1 + Part 2 的条数成为偶数）再加两根条，所以有效数据的条数仍是偶数，长条码中空着的校验格恰好正确。因此，仅凭数据轨看不出是哪种版式；时钟轨可以，条码相对于齿孔的长度也可以。所以本工具请用户数细条，并且当它在 31 格片条中看到这种特征时，会询问上排是否有 7 根细条。照片读取不受影响：它匹配的是完整的时钟图案，而两种时钟图案互不包含。

## 位序

所有数值都按读取顺序、高位在前写入。维基百科的示例在第 7–13 格中把 79 编码为 `1001111`；Lawley 给出的权重是第 7–13 格为 64 … 1、第 15–18 格为 8 … 1；zxing-cpp 用 `ToInt` 从最低索引开始往上读取字段；Zint 用 `z_bin_append_posn` 写入字段，这个函数先追加最高位。

## 奇偶校验

当且仅当 18 个有效数据位（Part 1、Part 2、帧号、半帧标志）中有奇数根条时，校验格才有条，所以有效数据加上校验位的条数总是偶数。各来源的说法不同，但意思一致：

| 来源 | 表述方式 |
|---|---|
| zxing-cpp | 校验位必须等于它之前所有数据位之和对 2 取模的结果（空白格为 0，不改变这个和） |
| Zint | 校验位 = 起始符之后每一位的异或 |
| alibosworth | “even parity over the 18 useful data bits”（对 18 个有用数据位做偶校验） |
| Mérino | 校验位为 1 表示“the sum of the previous bits should be odd”（前面各位之和应为奇数） |
| 维基百科示例 | 79-15 的帧 23 有 13 根有效数据条，校验格有条 |

维基百科里的说明句（“positions 1 through 12 plus the parity bit”，意为第 1 到第 12 位加上校验位）与它自己的表格不符；表格符合上述规则，所以这句话被当作措辞上的笔误。

## 起始符和终止符：两种等价的描述

维基百科和 Zint 描述的是 6 位的起始符 `101010` 和 4 位的终止符 `0101`。zxing-cpp 则把起始符看作 `10101` 后面跟一个总是 0 的数据位，把终止符看作 `101` 前面有一个总是 0 的位。两种描述对应的是同样的 31 格；空白的第 6 格和第 28 格把时钟轨两端的标记与数据区隔开，使第 7 格或第 27 格中的 1 不会与它们连在一起。

## 示例

各字段之间用空格隔开，顺序与上面的表格相同。

| DX 编号，帧 | 数据轨 | 来源 |
|---|---|---|
| 79-15, 23 | `101010 1001111 0 1111 010111 0 0 1 0101` | 维基百科示例；也从一张真实的柯达 BW400CN 负片上测得（[报告 05](05-reading-real-film.zh-CN.md)） |
| 95-14, 5 | `101010 1011111 0 1110 000101 0 0 1 0101` | alibosworth 的 Portra 160 示例 |
| 112-1, 10A | `101010 1110000 0 0001 001010 1 0 1 0101` | Mérino 的示例 |
| 47-1, 22A | `101010 0101111 0 0001 010110 1 0 0 0101` | 维基共享资源上的照片说明（Perutz Primera 200） |
| 127-15, 63A | `101010 1111111 0 1111 111111 1 0 0 0101` | Zint 测试向量（最大值） |
| 79-7，无帧号 | `101010 1001111 0 0111 0 0101` | Zint 测试向量（23 格版式） |

以上所有示例，加上 Zint 的其他所有测试向量，都是本项目单元测试（`tests/unit/codec.test.mjs`）的一部分，此外还有对全部 2,032 个可能的 DX 编号的穷举往返测试。

## 解码器执行的规则

| 检查项 | 原因 |
|---|---|
| 起始符和终止符 | 由格式规定（本工具会画出它们，但读取照片时会检查） |
| 第 14 格和第 26 格为空 | “unassigned … left blank”（未分配……留空），出自 ISO 1007（经维基百科转引）；zxing-cpp 会拒绝违反这一点的条码 |
| 奇偶校验 | 见上文 |
| Part 1 ≠ 0 | zxing-cpp 拒绝产品编号 0，2008 年的 I3A 列表也没有分配 0 |

奇偶校验不通过时，最可能是有一根条读错了。由于单个校验位无法指出是哪一根，本工具会列出所有能得到有效编码的单格改动，并把与已知胶片相符的排在前面。

## 字段的名称

| 本项目 | 柯达专利 | ISO 1007（经维基百科转引） | 其他名称 |
|---|---|---|---|
| Part 1 | product code（产品代码）；图 5 中为“film product class”（胶片产品类别） | film product class identification（胶片产品类别标识） | ProdCode（Pakon 扫描仪）、DXN1 |
| Part 2 | generation number（代号）；图 5 中为“film specifier”（胶片规格号） | film specifier（胶片规格号） | GenCode、DXN2 |
| Part 1-Part 2 | NAPM number（NAPM 编号） | DX number（DX 编号） | DX number |
| 带帧号的 31 格条码 | multi-field bar code（多字段条码） | — | “DXN code”（柯达的 EP 0838718） |
| 帧号字段 + 半帧标志 | frame number in half-frame intervals（以半帧为间隔的帧号） | frame number and half-frame indicator（帧号和半帧指示符） | “DXN”编号（维基百科，*DX encoding*） |

注意，Mérino 所说的“DXN1”和“DXN2”指 Part 1 和 Part 2，而柯达和维基百科用法中的“DXN”指的是帧号扩展。

## 读写这种条码的软件

- **zxing-cpp**（读码器）把条码输出为 `115-10/11A` 这样的文本：Part 1、Part 2，对于 31 格版式，还有斜杠后面的帧标签。本项目的可分享链接也用同样的形式（`?dx=79-15/23`）。它会拒绝未使用的格中有条、奇偶校验不通过或 Part 1 为 0 的条码，并接受最长 20 个相同格的连续段，这是有效数据轨中可能出现的最长连续段（例如 `96-0/0`）。
- **Zint**（生成器）接受同样的文本形式、“DX extract”（四位数编号，16 × Part 1 + Part 2，16 到 2047）或“DX full”（六位数暗盒编号），以及帧标签 `X`/`S`（62）、`00`/`K`（63）和 `F`（0）。
- 修改版的 Big Film Database 网站借助 zxing-cpp，用手机摄像头扫描 DX 片边码和暗盒条码（[报告 04](04-community-database.zh-CN.md)）。
